# 내 PC 전용 로컬 웹 사용법 — 0.1.4

이 버전은 화면을 Edge에서 보여주고, 문서는 PC 안의 Python 프로그램이 처리합니다. Python과 필요한 라이브러리는 Windows ZIP·EXE에 포함되어 있습니다. 업무 PC에 Python을 따로 설치하지 않습니다. 실행 도중 인터넷에서 내려받는 파일은 없습니다.

## 시작 전 확인

Windows 11 64비트 시험판입니다. 일반 사용자 권한으로 실행합니다. Windows 11·Edge 실기기 실행과 보안제품 호환성은 개발 환경에서 확인하지 못했습니다. 기관 반입·실행 허가를 먼저 받으세요. 실행 파일은 코드서명하지 않았으므로 SmartScreen 경고가 나타날 수 있습니다. 로컬 웹으로 바꿔도 실행 허용 문제가 자동 해결되는 것은 아닙니다.

실제 평가 양식의 자동 사업 연결, 총괄DB 셀 매핑과 공식 최종본 작성은 미구현입니다. 현재는 가상 규칙을 검증한 시험판입니다. 실제 작업의 목표는 작성취합.xlsx의 총괄DB이며 다른 시트는 이후 단계입니다. 실제 자료를 외부 개발 대화·사이트에 보내지 마세요.

## 1. ZIP으로 실행하기

1. BudgetOffline-0.1.4-Windows-x64.zip을 기관이 승인한 로컬 폴더에 저장합니다. 이전 버전에 덮어쓰지 않습니다.
2. ZIP에서 오른쪽 버튼 → Windows의 **모두 압축 풀기**를 선택합니다. ZIP 내부에서 바로 실행하지 마세요.
3. 압축을 푼 폴더에서 **실행.cmd**를 더블클릭합니다. runtime 폴더와 run_web.py가 같은 폴더에 있어야 합니다.
4. Edge가 열리고 **예산 근거 대조** 화면이 나타납니다. 명령 창은 프로그램이 실행되는 동안 열어 둡니다.
5. Edge가 자동으로 안 열리면 명령 창의 LOCAL_WEB_READY 뒤 주소 전체를 복사해 Edge 주소창에 붙여 넣습니다. 주소 끝의 # 뒤 접속키도 필요합니다. 이 주소는 다른 사람에게 공유하지 마세요.
6. 기존 프로젝트에 바로 자료를 넣기 전에 다음의 가상시험을 수행합니다.

단일 EXE를 허가받았다면 BudgetOffline-0.1.4-Windows-x64.exe를 더블클릭해도 같은 웹 화면이 열립니다. EXE는 사용자 LocalAppData에 실행 파일을 준비합니다. EXE가 관리자 권한을 물려받으면 제한된 일반 권한으로 자동 전환을 시도합니다. ZIP의 실행.cmd에는 자동 권한 전환이 없고, 높은 권한이면 중단합니다.

## 2. 접속 주소와 IP

주소 예: http://127.0.0.1:49152/#접속키

127.0.0.1은 ‘바로 이 PC’를 뜻합니다. 포트 번호(예: 49152)는 실행 때마다 Windows가 빈 번호로 배정합니다. 위 예시 주소를 직접 외워 입력하지 말고 실행 시 표시된 주소를 사용하세요.

192.168.180.198은 사용자 PC의 내부망 주소로 이해했습니다. 이 시험판은 그 주소에서 접속을 받지 않습니다. 같은 PC에서도 Edge에 127.0.0.1 주소를 사용합니다. 다른 PC나 인터넷에서 접속하는 기능은 제공하지 않습니다. 브라우저의 로그인·클라우드 동기화는 필요 없습니다. 기관의 승인된 브라우저 설정을 사용하세요.

## 3. 가상자료로 한 바퀴 시험

1. 화면의 프로젝트 폴더 전체 경로를 확인합니다. 기본값은 사용자 LocalAppData 아래 BudgetOfflineWork의 새로운 가상시험 폴더입니다. 기관이 승인한 별도 로컬 폴더로 바꿀 수 있습니다. 예: C:\Users\홍길동\BudgetOfflineWork\가상시험1
2. **가상자료로 시작**을 누릅니다. 가상 3부서 파일 6개와 근거 24개가 나타나야 합니다. 파일은 이미 앱에 들어 있으므로 실제 자료가 필요 없습니다.
3. **원문 근거와 연결** → 행의 **상세 확인**을 누릅니다. 원문값, 위치, 주변 설명, 단위 변환을 읽습니다.
4. 같은 업무 항목인지 부서·사업·기간·예산구분·지표·세부차원·집계수준·재원을 확인합니다. 검토자에 ‘가상시험자’, 이유에 ‘동봉 가상 정답의 의미와 단위 확인’을 입력하고 **연결 확인하여 저장**을 누릅니다.
5. 짝이 되는 한글·엑셀 근거를 각각 확인합니다. 동봉 예시에서 1,000천원과 1,000,000원은 원으로 맞추면 같습니다. 이를 정규화, 즉 같은 단위로 맞추는 작업이라고 부릅니다.
6. **대조와 승인** → 해당 행 **상세 확인**에서 두 근거와 비교 판정을 확인합니다. 정확 일치 또는 변환 후 정확 일치이며 미해결 조건이 없어야 **승인**할 수 있습니다. 검토자와 이유를 별도로 기록합니다.
7. **검토용 초안 엑셀**을 누릅니다. 미검토·보류 항목도 보고서에 남습니다. 아래 결과에 저장 경로와 **사본 다운로드** 버튼이 나타납니다.
8. **승인 데이터 엑셀**은 승인된 값만 출력합니다. 필수 항목이 누락되면 중단될 수 있습니다. 공식 최종본 기능은 잠겨 있습니다.
9. **프로젝트 백업**으로 백업을 만들고 저장 경로를 기록합니다.
10. **프로젝트 닫기** → 프로젝트 경로를 존재하지 않는 새 경로로 바꾸기 → **백업 복구** → 백업 ZIP의 전체 경로 입력 순서로 복구합니다. 근거·승인이 유지되는지 확인합니다.

## 4. 파일 가져오기와 누적

새 프로젝트를 만들거나 기존 project.db가 있는 폴더를 엽니다. ‘파일 선택’에서 여러 파일을 선택하거나 ‘폴더 선택’으로 제출자료 폴더를 선택합니다. 파일은 한 번에 2,000개, 하나당 50MiB까지 가능합니다. 브라우저가 이 PC의 127.0.0.1 처리 프로그램으로 파일 내용을 전달하고, 프로그램이 원본 사본을 보존합니다. 외부 서버 전송이 아닙니다.

한 파일이 실패해도 다음 파일은 계속 처리합니다. 작업 결과에서 처리 실패·미지원·제외를 꼭 확인하세요. ‘가져오기 취소’는 현재 파일이 끝나면 남은 파일을 중단합니다. 가져오는 동안 브라우저를 닫거나 종료하지 마세요. 같은 내용은 이름을 바꿔도 SHA-256이라는 내용 지문으로 확인하여 중복 집계하지 않습니다.

새 양식은 자동 연결하지 않고 보류합니다. HWP는 텍스트 추출만 제한 지원하며 표 의미 해석은 검증되지 않았습니다. 수식·숨김 데이터·단위 불명·근사값 등은 자동 승인하지 않습니다. 실제 원문은 기관 안에서 한컴·Excel로 직접 확인하세요. 화면의 ‘원본 사본 받기’는 읽기용 추가 사본을 내려받으며 원본을 실행하지 않습니다.

## 5. 수정본과 검토

근거 행 상세에서 검토자·이유를 쓰고 ‘근거 제외’ 또는 ‘근거 다시 채택’으로 사용할 버전을 선택합니다. 파일 전체는 파일 행 상세의 ‘파일 제외/복원’을 사용합니다. 수정본이 들어왔다는 이유만으로 최신본을 채택하지 않습니다. 채택 변경·재처리·규칙 변경 후 승인이 재검토로 바뀌는지 확인하세요.

대조 행에서 ‘검토 중’, ‘승인’, ‘보류’, ‘제외’를 구분합니다. 문제가 있는 항목은 승인 버튼으로도 강제 통과할 수 없습니다. 숫자가 같아도 의미가 다르면 연결하지 않습니다. 원문에 없는 값을 만들어 넣는 수동 정정 기능은 제공하지 않습니다.

## 6. 저장·다운로드·종료

완료된 변경은 프로젝트 DB에 저장됩니다. 엑셀은 프로젝트의 exports 폴더에 먼저 저장합니다. 웹 화면의 다운로드는 브라우저 다운로드 폴더에 만드는 추가 사본입니다. Windows의 동기화 다운로드 폴더는 기관 규정을 확인하세요. long은 지표 하나를 한 행에 쓰는 형태, wide는 같은 사업의 지표를 옆 열에 펼치는 형태입니다. 임의 합산으로 충돌을 해결하지 않습니다.

백업은 프로젝트 옆 BudgetOfflineBackups 폴더에 새로운 이름으로 저장합니다. DB뿐 아니라 원본·설정·승인·출력 연결을 포함합니다. 이름이 이미 있는 파일을 덮어쓰지 않습니다. 다른 안전한 저장소로의 이동·암호화는 기관 규정에 따라 수행하세요.

마칠 때 **저장하고 프로그램 종료** → 확인 → ‘프로그램을 종료했습니다’ 안내 확인 → 탭 닫기 순서입니다. 탭만 닫으면 서버는 계속 실행됩니다. ZIP 실행 창에서 Ctrl+C로 종료할 수도 있지만 처리 중에는 사용하지 마세요. 강제 종료했다면 재실행 후 프로젝트를 열고 상태·무결성·실패 목록을 확인합니다.

## 7. 문제가 생겼을 때

- 접속할 수 없음: 실행 창이 살아 있는지, 가장 최근의 전체 접속 주소인지 확인합니다. 192.168.180.198 주소나 예전 포트로 접속하지 않습니다.
- 접속 확인 실패: 실행 파일이 열어 준 전체 주소(# 뒤 접속키 포함)를 사용합니다. 외부 웹페이지에 주소를 붙이거나 접속키를 공유하지 않습니다.
- 포트·실행이 차단됨: 기관 담당자가 이 로컬 웹 실행 환경을 승인해야 합니다. 보안 기능을 끄지 마세요. 이전 모든 IP 차단 규칙은 웹과 충돌할 수 있으므로 담당자가 새 규칙과 구분해 검토합니다.
- 작업 실패: 파일 잠금·남은 공간·로컬 폴더 권한을 확인합니다. 실제 자료·화면·로그를 외부 개발자에게 자동 전송하는 기능은 없습니다.
- 경로가 길거나 틀림: 전체 로컬 경로를 입력합니다. 복구 폴더는 아직 존재하지 않아야 합니다. 프로그램 준비 폴더 안에 업무 프로젝트를 만들지 않습니다.
