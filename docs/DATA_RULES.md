# 값과 연결 규칙

## 가상 규칙과 미확정 범위

프로그램 버전은 0.1.1, DB 구조 버전은 1, 기본 규칙은 `가상규칙-1`입니다. `rules/demo-v1.json`은 새 프로젝트의 초기 규칙입니다. 이후 프로젝트는 자기 DB 안의 규칙을 사용합니다. 파일을 고치기만 해서는 열린 프로젝트 규칙이 바뀌지 않습니다.

이 문서의 열·코드·셀 위치는 **가상시험 전용**입니다. 실제 기관 양식의 최종 열이나 매핑으로 확정하지 않았습니다. 설정의 `actual_template_validated`는 false, `final_mapping`은 null이어야 합니다. 시험판은 이를 바꿔 공식 출력을 켜는 것을 거부합니다.

## 업무 키

업무 키는 어떤 값인지 식별하는 항목의 묶음입니다. 예를 들어 숫자 100만원만으로는 어느 사업인지 모릅니다. 이 시험판에서는 다음 8개 문자열이 모두 같아야 같은 값의 후보입니다.

`부서코드 + 사업코드 + 기간 + 예산구분 + 지표코드 + 세부차원 + 집계수준 + 재원`

예: `D001 / P001 / 2026 / 시행예산 / 시행예산 / 전체 / 사업총액 / 전체`.

사업명 유사도, 파일명, 금액 일치, 들어온 순서로 연결을 확정하지 않습니다. 가상 양식에 코드가 있어도 모든 근거는 연결 미확인 상태로 시작합니다. 코드가 없는 실제 자료는 기관이 검토한 식별 체계를 수동 연결 화면에 입력해야 합니다. 코드 앞자리 0은 문자열로 보존합니다. 숫자 셀의 표시 서식으로 만든 앞자리 0은 자동 신뢰하지 않습니다.

## 가상 양식 읽기

XLSX는 시트 A1의 `가상예산-v1` 표식과 처음 100행 안의 정확한 10개 머리글을 찾습니다. 가상 머리글은 위 8개 키 뒤 `값`, `단위`입니다. HWPX는 같은 표식과 같은 머리글을 가진 단순 표만 구조 규칙으로 읽습니다. 머리글·표 위치가 바뀌어도 정해진 구조를 찾을 수 있어야 합니다. 병합·숨김·필터·수식·추가 열은 경고와 함께 보류합니다.

일반 양식은 이 규칙을 자동 적용하지 않습니다. 사람은 셀 또는 문단 근거를 확인한 뒤 수동 연결할 수 있습니다. HWP는 CFB라는 이진 파일 구조의 FileHeader와 BodyText 텍스트를 제한적으로 읽습니다. 실제 한컴 문서의 표 의미·글자 순서·페이지 호환성을 검증하지 않았습니다.

## 숫자, 단위와 결측

정규화란 서로 비교할 수 있도록 같은 단위로 맞추는 일입니다. `1,000천원 × 1000 = 1,000,000원`이 예입니다. 쉼표와 문자 폭을 정리하는 단계와 단위를 곱하는 단계를 별도로 기록합니다.

| 입력 | 보존·판정 |
|---|---|
| 빈칸 | 빈칸. 0으로 바꾸지 않음 |
| 0 | 숫자 0 |
| - | 대시 의미 미확인 |
| 해당 없음 | 해당 없음. 숫자로 비교하지 않음 |
| 약 1.2억원 | 표시 정밀도 확인 필요 |
| (100), △100 | 감액 규칙 미확인 |
| -100 | 명시적 음수 십진수. 업무 키·단위와 사람 확인 필요 |
| 단위 없음·단위 충돌 | 승인 차단 |

금액은 Python Decimal, 즉 정확한 십진수로 계산합니다. XLSX 숫자 셀도 XML의 저장 문자열을 사용합니다. 허용오차는 0입니다. 매우 긴 숫자는 자릿수 제한으로 보류합니다. 단위는 원·천원·백만원·억원, 명, 건, %, 비율을 가상 규칙으로 제공합니다. 원화와 인원은 서로 같은 숫자여도 비교 통과하지 않습니다.

`12.5 %`와 `0.125 비율`은 두 단위가 명시되면 같습니다. Excel의 % 표시형식만으로 의미를 추측하지 않으며 해당 셀은 보류합니다. 원문을 확인한 수동 근거 선택은 별도 이력으로 남습니다. 표시 반올림·절사·허용 오차 규칙과 승인된 예외 출력은 구현하지 않았습니다.

수식은 계산하지 않습니다. 캐시가 있어도 최신 계산 결과라고 확인할 수 없어 모두 보류합니다. 외부 참조를 갱신하지 않습니다. 합계·소계·전년 차액·인원×단가·집행률·사용률을 자동 계산하지 않습니다. 사용자 요청에 따라 가상자료에 시행예산, 전년도예산, 집행률, 예산사용률을 넣었지만 각각 **제출된 독립 지표**로 비교합니다. 전년 대비 차액의 산식은 미확정입니다.

## 중복·버전·승인

동일 SHA-256 파일은 같은 파일 ID를 참조하는 가져오기 이력만 늘어납니다. 같은 키에 같은 종류의 근거가 여러 개면 값이 같아도 중복·수정본 확인이 필요합니다. 사람은 근거를 제외·다시 채택할 수 있으며 원본과 이력은 남습니다.

한글 1개 근거와 엑셀 1개 근거, 모든 키 확인, 숫자·단위 해석 가능, 미해결 추출 경고 없음, 원본 해시 정상일 때만 정확 비교를 통과할 수 있습니다. 어떤 원본이 바뀌거나 근거·키·단위·채택·규칙이 바뀌면 관련 결정의 지문이 달라져 재검토로 바뀝니다. 새 근거는 같은 값이어도 이전 승인을 자동 재사용하지 않습니다.

출력에서도 현재 판정과 승인을 다시 확인합니다. 화면에서 버튼을 우회해 함수를 호출해도 미통과 승인·미검증 공식 출력은 거부합니다. 단, 사용자가 프로그램이나 DB를 직접 변조하는 것까지 막는 제품은 아닙니다.

## long / wide

long은 지표를 아래로 쌓은 표입니다. 한 키당 한 행이며 출처는 별도 `원문근거` 시트와 연결합니다. 근거 두 개를 예산 두 건으로 더하지 않습니다. 미해결 키는 초안에서 값 없이 남깁니다.

wide는 지표코드를 제외한 7개 키로 행을 묶고, 지표별 값·단위·항목 ID를 옆으로 펼칩니다. 같은 위치에 두 값이 있으면 오류로 중단합니다. 첫 값·최대값·합계를 임의로 쓰지 않습니다. 자동 소계도 없습니다. 실제 제출 양식의 반복 하위지표 표현은 미확정입니다.

## 필수 목록과 최종 매핑

`samples/필수항목.json`의 departments는 부서 코드·표시 이름, keys는 기대하는 8개 키의 목록입니다. JSON은 글자로 된 설정 파일이며 프로그램 코드를 실행하지 않습니다. 필수 목록을 등록하면 없는 항목을 누락으로 표시합니다. 부서만 등록하고 필수 항목을 정의하지 않으면 완전성을 판단하지 않습니다.

실제 제출 엑셀, 허용 셀, 기존 수식·서식·인쇄 설정, 예외 승인 규칙은 검증 전입니다. `inspect_mapping`은 개발시험에서 빈 셀·중복 충돌만 확인하는 도구이며 사용자 최종 출력 기능이 아닙니다. 실제 양식 보존 시험을 수행하기 전까지 공식 출력은 제공하지 않습니다.
