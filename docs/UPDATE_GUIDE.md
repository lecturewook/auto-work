# 업데이트·백업·복구

## 0.1.1에서 0.1.2로 바꾸기

1. 기존 앱을 닫고 프로젝트 전체를 백업합니다. 실행하지 못하는 경우 닫힌 상태에서 프로젝트 폴더 전체를 복사해 보관합니다. 기존 프로그램 폴더 안에 프로젝트가 있다면 먼저 별도 작업 위치로 전체를 복사하세요.
2. 새 **BudgetOffline-0.1.2-Windows-x64.exe**의 출처·해시·기관 반입 허가를 확인합니다. EXE를 별도 로컬 위치에 놓고 일반 더블클릭합니다. Python 설치·기존 ZIP 덮어쓰기가 필요 없습니다.
3. **가상자료로 시작**으로 새 시험 작업을 만들어 연결·승인·출력·백업복구를 확인합니다. 실제 프로젝트에 가상자료를 넣지 않습니다.
4. **프로젝트 열기**로 기존 작업의 복사본을 열어 파일·근거·승인 수를 확인합니다. DB 구조 1, 가상규칙-1, 비교·승인 조건은 동일하며 DB 변환은 없습니다.
5. 기관 담당자는 새 실행 파일과 자동 준비된 런타임 경로의 방화벽·실행 허가를 다시 확인합니다. 예전 프로그램 경로의 규칙이 새 경로에 자동 적용되지는 않습니다.
6. 문제가 있으면 0.1.1 프로그램과 그에 대응하는 작업 백업으로 돌아갑니다. 0.1.0의 관리자 실행 방식으로 돌아가지 않습니다.

EXE는 `%LOCALAPPDATA%\BudgetOffline\app\버전-묶음지문`에 버전별로 프로그램을 준비하며 이전 버전을 덮어쓰지 않습니다. 이 안에 업무 프로젝트를 만들 수 없습니다. 오래된 프로그램 캐시·시작 로그의 삭제는 작업을 백업하고 기관 보관 규칙을 확인한 뒤 담당자가 합니다. 프로젝트·원본은 사용자가 지정한 별도 작업 위치에 있습니다.

## 0.1.0에서 0.1.1로 바꾸기

0.1.0의 관리자 실행 요구를 없애고, 0.1.1에서는 오히려 관리자 실행을 차단합니다. 기존 프로그램을 종료한 상태에서 프로젝트 폴더 전체를 기관 승인 경로로 복사해 보존하세요. 새 묶음을 별도 프로그램 폴더에 풀고 실행.cmd를 일반 더블클릭합니다. 관리자 상태의 터미널·파일 탐색기에서 실행하지 마세요.

기존 프로젝트가 일반 계정에서 열리지 않으면 담당자가 **그 작업 폴더만** 필요한 권한으로 조정하거나 일반 계정의 승인된 경로로 복사해야 합니다. 관리자 실행으로 우회하지 않습니다. 새 버전에서 정상 열림을 확인한 뒤 프로그램의 백업·복구 시험을 합니다. DB 구조 버전 1과 가상규칙-1은 같고 DB 변환은 없습니다. 비교·승인 규칙의 변경은 없지만 가상자료 재시험은 수행하세요. 기존에 잘못 저장된 프로젝트 표시 이름(exports)은 이 버전이 자동으로 바꾸지 않습니다. 새 프로젝트 이름 저장 문제는 수정했습니다.

## 업데이트 종류 먼저 구분하기

| 변경 | 처리 |
|---|---|
| 부서 추가·필수 사업 추가 | `필수항목.json` 구조의 목록을 검토해 다시 등록. 기존 목록을 대체하므로 전체 부서·필수 키를 포함 |
| 이름 대응·사업 연결 수정 | 근거별 연결 확인/수정. 이전 키·새 키·검토자·이유 기록, 영향받는 승인 재검토 |
| 단위 배수·명칭 추가 | 새 버전 이름의 규칙 JSON 작성, 별도 복사 프로젝트에서 검증. 배수 잘못 입력은 큰 금액 오류가 됨 |
| 새 지표 | 기존 8개 키와 단순 표로 표현 가능하면 필수 목록·가상자료로 시험. 계산식은 지원하지 않음 |
| 표 구조·HWP 추출·실제 셀 매핑 변경 | 개발자 코드 수정과 새 양식 검증이 필요 |
| 프로그램 교체 | 새 오프라인 묶음으로 별도 폴더에서 시험 후 적용 |

설정 파일에는 실행 코드를 넣을 수 없습니다. 실제 양식을 검증하지 않은 채 표식만 `가상예산-v1`로 바꿔 통과시키지 마세요. 프로그램 파일의 `rules/demo-v1.json`을 직접 고치면 새 프로젝트에만 적용됩니다. 기존 작업에는 **작업 관리 → 규칙 JSON 변경**을 사용해야 이력이 남습니다.

## 평소 백업

1. 현재 가져오기를 끝냅니다. 원본 무결성 확인을 실행합니다.
2. **작업 관리 → 프로젝트 백업**을 누릅니다.
3. 현재 프로젝트 밖의 기관 승인 위치에 새 이름을 정합니다. 예: `C:\BudgetBackup\2026_가상시험_01.zip`. 같은 이름을 덮어쓰지 않습니다.
4. 백업 완료 메시지를 확인합니다. 이 ZIP에는 DB, 원본 사본, 정상 출력이 들어 있습니다. 규칙·연결·승인·이력은 DB 안에 있습니다. 작업 사본은 원본에서 다시 만들므로 중복 저장하지 않습니다.
5. 해당 버전의 프로그램 EXE 또는 설치 ZIP과 안내서도 별도로 보관합니다. 프로젝트 백업에 프로그램 실행 파일은 들어 있지 않습니다.
6. ZIP을 실제로 복구해 보세요. 백업 파일이 존재하는 것만으로 성공이라고 판단하지 않습니다.

일반 파일 탐색기로 실행 중인 project.db 한 개만 복사하는 것은 전체 백업이 아닙니다. 원본과 규칙·승인 연결을 잃을 수 있습니다. 내보낸 엑셀도 DB 백업을 대신하지 않습니다.

## 복구 시험

1. 창 위 **백업 복구**를 누릅니다. 프로그램이 만든 ZIP을 고릅니다.
2. 상위 로컬 폴더를 고르고 아직 없는 새 이름 `2026_가상시험_복구확인`을 입력합니다.
3. 프로그램이 압축 경로, 파일별 해시, DB 구조, 원본 해시를 확인합니다. 기존 프로젝트에 덮어쓰지 않습니다.
4. 현재 프로젝트를 닫고 **프로젝트 열기**로 새 복구 폴더를 엽니다.
5. 파일 수, 승인 수, 원문 위치, 규칙 버전, 정상 출력 파일을 원래 작업과 대조합니다.
6. 가상자료에서 승인 데이터 출력을 다시 해 봅니다. 업무자료는 기관 안에서만 검사합니다.

백업 자체는 암호화되어 있지 않습니다. 프로그램은 최대 해제 5GiB·20,000항목 범위의 백업을 복구합니다. 이 한도를 넘는 업무는 운영 도입 전 별도 검증해야 합니다. 외부 사람이 만든 임의 ZIP·DB는 신뢰하지 마세요.

## 프로그램 업데이트 순서

1. 현재 프로젝트 전체 백업과 현재 프로그램 ZIP을 확보합니다. 프로그램·DB·규칙 버전을 적어 둡니다.
2. 새 묶음의 출처와 해시를 기관이 확인한 기준으로 검사합니다. 해시가 일치해도 배포자 신원을 자동 보증하지 않습니다.
3. 기존 프로그램을 지우지 말고 새 폴더에 압축을 풉니다. 예: `C:\BudgetTrial_0_2_0`. 새 경로는 방화벽 규칙도 별도로 적용합니다.
4. 기존 백업을 **새 시험용 폴더**로 복구합니다. 운영 작업 원본으로 먼저 시험하지 않습니다.
5. 새 프로그램에서 동봉 가상시험을 실행합니다. 이전 버전의 기대결과와 새 결과를 비교합니다. 잘못 통과한 항목이 하나라도 있으면 중단합니다.
6. CHANGELOG의 DB 변환 여부를 봅니다. 현재 버전 1은 다른 DB 구조 버전을 거부하며 자동 변환 도구가 없습니다. 앞으로 DB 구조가 바뀌면 별도 검증된 변환 절차가 필요합니다.
7. 규칙·추출 결과가 바뀌면 재처리·연결 확인·재승인을 합니다. 재처리는 기존 근거를 이력으로 남기고 새 근거를 만들므로 승인 재사용을 피합니다.
8. 복사 프로젝트의 원본·이력·승인·출력을 확인한 뒤 기관이 운영 적용을 결정합니다. 실제 PC 검증을 개발환경 성공으로 대신하지 않습니다.

## 실패했을 때 되돌리기

새 프로그램을 닫습니다. 이전 프로그램 폴더를 다시 사용하고, 업데이트 **전** 백업을 새 폴더에 복구합니다. 이전 프로그램과 그때의 DB·규칙을 세트로 되돌립니다. 새 버전에서 변환한 DB를 옛 프로그램에 억지로 열지 않습니다.

프로그램 제거는 종료 후 기관 기준에 따라 프로그램 폴더를 삭제합니다. 방화벽 규칙 제거가 필요하면 담당자가 PowerShell에서 `tools\windows_policy.ps1 -Mode Remove`를 해당 설치 폴더에서 실행합니다. 이 명령은 그 위치의 프로그램 규칙만 제거하도록 작성했으며 Windows 실기기 검증은 아직입니다. 프로젝트·백업은 별도 위치에 남아 있으므로 보관규칙을 확인한 뒤 따로 처리합니다.
