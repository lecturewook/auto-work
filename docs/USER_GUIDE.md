# 사용법

## 1. 프로젝트 만들고 다시 열기

프로젝트는 파일 목록·원본·검토 이력을 묶어 저장하는 작업 폴더입니다. 창 위 **새 프로젝트**를 누르고 저장할 상위 폴더와 새 이름을 입력합니다. 한 번 만든 작업을 이어갈 때는 **프로젝트 열기**로 `project.db`가 들어 있는 폴더를 선택합니다. DB는 프로그램이 쓰는 장부 파일입니다. Excel로 열거나 직접 고치지 마세요.

각 작업은 끝날 때 자동 저장합니다. 별도 저장 버튼은 없습니다. **작업 관리 → 프로젝트 닫기** 또는 창의 X 버튼으로 종료합니다. 다른 프로젝트를 열려면 현재 작업을 먼저 닫습니다. 가져오는 중에는 취소를 누른 뒤 기다려야 닫을 수 있습니다. 파일 하나는 최대 30초까지 기다릴 수 있습니다.

한 프로젝트를 두 창에서 동시에 열면 두 번째 창에 사용 중 안내가 나옵니다. 강제 종료 후에는 운영체제가 잠금을 해제하므로 `.lock` 파일을 직접 지울 필요가 없습니다. 공유 폴더 동시 편집은 지원하지 않습니다.

## 2. 파일 가져오기

**파일 가져오기 → 파일 선택**에서 Ctrl 키를 누르며 여러 파일을 고릅니다. 폴더 전체를 읽으려면 **폴더 선택**을 누릅니다. 하위 폴더의 HWP/HWPX/XLSX/XLS/XLSM을 찾되 한 번에 2,000개까지 처리합니다. XLS와 XLSM은 미지원으로 남습니다. 임의 ZIP 묶음 가져오기는 없습니다. ZIP은 프로그램 백업 복구에만 사용합니다.

가져오기란 PC 안에서 복사하는 작업입니다. 외부 서버로 올리지 않습니다. 파일 목록에는 원래 이름·역할·처리 상태·제외 여부·이유·파일 ID가 나옵니다. 행을 누르면 SHA-256, 보관 위치 등 상세 정보를 아래에서 봅니다. SHA-256은 내용이 같으면 같은 값이 나오는 지문입니다. 파일명이 달라도 내용 지문이 같으면 재가져오기로 기록하고 다시 더하지 않습니다.

원본 사본은 `originals`, 읽기에 쓰는 사본은 `work`에 있습니다. 원본 사본에는 읽기 전용 속성을 설정하지만 관리자는 바꿀 수 있습니다. 임의로 고치면 다음 검증에서 해시 불일치가 발생합니다. 프로그램은 사용자가 처음 선택한 원본 파일을 수정하지 않습니다.

진행 표시 아래 **가져오기 취소**를 누르면 지금 읽는 파일이 끝난 뒤 다음 파일을 가져오지 않습니다. 완료한 파일은 저장합니다. 남은 파일은 `미처리`로 결과창에 알립니다. 미처리 파일을 실제로 복사해 저장한 것처럼 보이지 않습니다. 취소된 목록 자체는 DB의 파일 목록에 들어가지 않으므로 다시 폴더를 선택하세요. 이미 처리한 내용은 중복으로 더해지지 않습니다.

## 3. 처리 상태 이해하기

| 구분 | 표시 | 의미 |
|---|---|---|
| 파일 읽기 | 처리 중 / 처리 성공 | 읽는 중 / 지원한 구조를 읽음. 값 승인과는 다름 |
| 파일 읽기 | 처리 실패 | 손상·시간 제한·안전 제한 등으로 읽지 못함 |
| 파일 읽기 | 미지원 | 검증하지 않은 양식·확장자. 일부 근거를 읽었어도 완료 아님 |
| 파일 사용 | 사용 / 제외 | 비교에 사용할지 결정한 상태 |
| 연결 | 연결 불명 / 확인 | 사람이 업무 키·단위를 확인했는지 |
| 비교 | 정확 일치 / 변환 후 정확 일치 | 명시된 의미와 단위로 정확히 같음. 아직 승인 아님 |
| 비교 | 불일치 / 누락 / 단위 불명 / 추출 실패 | 해당 문제를 해결하기 전 승인 불가 |
| 비교 | 중복·수정본 확인 필요 | 같은 업무 키의 한글 또는 엑셀 근거가 여러 개 |
| 업무 승인 | 미검토 / 검토 중 / 승인 / 보류 / 제외 / 재검토 필요 | 사람이 내린 업무 결정 |
| 출력 이력 | 반영 준비 / 반영 완료 / 반영 실패 | 결과 파일 작성 상태. 공식 제출 승인과 다름 |

대기 중 파일은 가져오기 진행 건수에 나타납니다. 아직 복사하지 않은 파일을 DB에 정상 파일로 기록하지 않습니다. 승인 뒤 관련 자료·키·규칙이 바뀌면 `재검토 필요`가 됩니다. 이전 승인 기록은 이력에 남습니다.

## 4. 연결과 원문 확인

**연결·원문 근거** 탭에서 행을 선택합니다. 아래 칸에서 원문 표기, 파일 이름, 시트·셀 또는 문단·표 위치, 주변 내용, 단위 변환 과정을 봅니다. 실제 페이지 번호를 만들지 않습니다. 프로그램 안에는 원본 문서의 전체 화면 미리보기가 없으며 해당 위치로 한컴을 자동 이동시키는 기능도 없습니다.

원문 화면이 필요하면 파일 목록에서 `work` 위치를 확인하고 기관이 승인한 한컴·Excel로 직접 여세요. 외부 링크 갱신·매크로 실행 요청은 허용하지 않습니다. 원본 사본 대신 작업 사본을 사용하고, 작업 사본을 바꿔도 DB의 추출값은 자동 변경되지 않는다는 점에 주의하세요. 정정자료는 별도 파일로 받아 다시 가져오는 것이 원칙입니다.

**연결 확인/수정**을 누르면 다음 8개를 확인합니다: 부서코드, 사업코드, 기간, 예산구분, 지표코드, 세부차원, 집계수준, 재원. `전체`는 이 가상시험에서 해당 구분 전체를 뜻합니다. 실제로 불명확한 것을 `전체`로 채워 통과시키지 마세요. 검토자 이름과 확인 이유도 적습니다.

예: “가상부서 D001의 P001, 2026년 시행예산 총액, 재원 전체임을 가상 정답과 대조함”. 실제 양식의 코드는 여기서 임의로 정하지 않습니다. 실제 연결 규칙은 업무 PC에서 기관 담당자가 정해야 합니다.

## 5. 미지원 문서의 수동 근거

새 양식 XLSX는 셀 문자열, HWPX는 문단 문자열을 읽어 근거로 제시할 수 있습니다. HWP 5도 텍스트 레코드를 시도하지만 표의 행·열 관계는 검증하지 않았으므로 미지원으로 표시합니다. 읽을 수 없는 HWP는 실패 이유가 나옵니다. 스캔 이미지에서 숫자를 읽는 OCR 기능은 없습니다.

원문을 직접 확인할 수 있을 때만 **원문에서 수동 값 선택**을 누릅니다. 예를 들어 `가상부서 시행예산 1,000천원`에서 `1,000`을 고르고 단위를 `천원`으로 지정합니다. 선택한 숫자는 원문에 실제로 있어야 합니다. 원래 근거는 제외 상태로 보존하고 새 수동 근거에 부모 ID를 연결합니다. 이 값은 자동 추출이라고 표시하지 않습니다.

수식·외부 참조·오류 셀을 이 기능으로 통과시킬 수 없습니다. `약`, 감액 기호를 지우거나 숫자 자릿수를 잘라 확정하는 것도 허용하지 않습니다. 기관 승인 수동 정정값을 입력하는 기능은 아직 없습니다. 정정자료를 새로 받아야 합니다.

## 6. 대조, 중복과 수정본

**대조·승인·수정본**에서 한글 근거와 엑셀 근거를 나란히 봅니다. 각각 여러 파일에 있어도 업무 키가 같으면 함께 표시됩니다. 같은 쪽에 근거가 여러 개 있으면 값을 임의로 고르지 않습니다.

연습: 정상자료를 확인·승인한 뒤 `samples\주의자료\D001_수정본.xlsx`를 가져옵니다. 기존 1,000,000원과 새 1,000,001원이 동시에 남고 이전 승인이 무효화됩니다. 새 근거의 연결을 확인하면 `중복·수정본 확인 필요`가 됩니다.

채택하려는 버전을 원문과 제출 규칙으로 정하세요. **연결·원문 근거 → 근거 채택/제외**에서 채택하지 않을 행을 제외하고 이유를 남깁니다. 단순히 나중에 가져왔다고 최신으로 정하지 않습니다. 잘못 제외했으면 같은 버튼으로 다시 채택할 수 있습니다. 파일 전체를 제외하려면 **파일 가져오기 → 파일 제외/복원**을 사용합니다. 원본은 삭제하지 않습니다.

한글과 엑셀 중 하나만 새 버전으로 바꾸면 `불일치`가 생길 수 있습니다. 숫자를 억지로 맞추지 말고 정정자료를 요청합니다. 이전 승인과 출력은 역사 기록으로 남으며, 이미 밖으로 복사한 엑셀을 프로그램이 자동 회수하지는 못합니다.

## 7. 승인과 보류

비교 판정이 `정확 일치` 또는 `변환 후 정확 일치`인 한 행만 **선택 항목 승인**할 수 있습니다. 검토자와 이유를 입력합니다. 검토자 이름은 본인 입력 기록이며 전자서명·로그인 인증이 아닙니다. 별도 결재자 권한 관리도 없습니다.

원문이 애매하면 **보류**, 확인 중이면 **검토 중**을 선택합니다. 전체 승인 기능은 없습니다. 같은 값이 두 문서에 있어도 같은 오타일 수 있으므로 일치가 실제 예산의 진실성을 증명하지 않습니다.

## 8. 미리보기와 내보내기

**취합 미리보기**는 long 구조로 한 업무 키당 한 행을 보여줍니다. 미승인 행도 볼 수 있고, 중복·불일치는 대표 숫자를 비워 둡니다. wide 구조는 출력 XLSX의 `wide` 시트에서 확인합니다. 화면에는 wide 피벗 편집기나 최종 제출 양식 미리보기가 없습니다.

- **검토용 초안 저장**: 미해결 항목도 포함합니다. 비교를 통과하지 않은 항목의 표준값은 비어 있습니다.
- **승인 데이터 저장**: 현재 검증을 통과하고 승인한 값만 long/wide에 넣습니다. 다른 시트에는 미해결과 전체 근거를 포함합니다. 부분 승인 출력일 수 있으므로 완전한 최종본이라고 해석하면 안 됩니다.

결과는 `exports`의 새 XLSX로 만듭니다. 이전 결과를 덮어쓰지 않습니다. 모든 숫자는 Excel의 자동 반올림을 피하려고 **텍스트 셀**로 저장합니다. 값은 정확히 보존되지만 자동 합계·수식 계산용 숫자 셀은 아닙니다. 실제 최종 양식의 숫자 형식은 추후 따로 검증해야 합니다.

`원문근거`의 근거 ID와 `long`의 근거 ID를 연결하면 파일·위치·원문·변환 과정으로 되짚어갈 수 있습니다. `부서현황`은 제출 근거 있음과 필수 항목 승인 완료를 구분합니다. 필수 목록이 없으면 완전성을 판단할 수 없습니다. 결과 자체에도 이 경고를 씁니다.

## 9. 검색·백업·종료

화면 위 검색창에 `D001 2026 시행예산`처럼 띄어 쓰면 모든 단어가 있는 행을 찾습니다. 옆 목록으로 오류·승인 상태를 좁힙니다. 이 기능은 표시를 숨길 뿐, 숨긴 문제를 해결하거나 승인하지 않습니다.

작업을 마치면 **작업 관리 → 프로젝트 백업**을 눌러 프로젝트 밖에 새 ZIP을 저장합니다. 백업을 다른 보호된 로컬 위치에 보관하는 방법은 기관 규정에 따릅니다. 복구 방법은 UPDATE_GUIDE.md를 보세요. 프로그램과 DB를 함께 보관해야 이전 버전으로 되돌릴 수 있습니다.
