# 시험 결과 — 0.1.0

시험일: 2026-10-31 (한국 시간 기준). 실제 업무자료는 사용하지 않았습니다. 이 결과는 시험한 가상자료에 한정되며 모든 미래 문서의 무오류를 보장하지 않습니다.

## 환경과 범위

- Linux x86-64, 커널 6.18.57, glibc 2.41, Python 3.12.14. 실행 환경에서 CPU 5개로 표시됨.
- openpyxl 3.1.5, PySide6/Qt 6.8.3, defusedxml 0.7.1, olefile 0.47, pytest 8.3.5.
- Windows 묶음은 CPython 3.12.10 x64와 Windows용 wheel을 조립함. Windows 실행·관리자 검사·방화벽 스크립트·한컴/Excel 실기기 동작은 **미실시**.
- HWPX는 XML/ZIP 표 구조를 생성, XLSX는 실제 XLSX 패키지를 생성. HWP는 OLE+HWP 5 헤더+압축 텍스트 레코드를 생성. 이름만 바꾼 텍스트를 HWP라고 시험하지 않음. 다만 한컴 저장 문서·렌더링 검증은 없으므로 HWP 자동 표 지원을 주장하지 않음.
- 정답은 가상 규칙으로 명시적으로 작성하여 Decimal 값·단위·키·상태와 비교. **업무 담당자의 독립적인 정답 검수는 미실시**.

시험 도구는 정해진 가상 키를 확인하는 호출을 자동 수행합니다. 제품 화면에는 실제 자료 자동 연결·일괄 승인 기능이 없습니다. 따라서 업무 담당자의 수동 검토 시간을 위 처리시간에 포함했다고 해석하면 안 됩니다.

## 오프라인·통신·화면

1. `unshare -Urn`으로 별도 Linux 네트워크 공간을 만들고 인터페이스가 loopback 1개뿐임을 확인했습니다. 이 공간에서 43개 기능 시험이 통과했습니다. 별도 오프라인 실행에서 GUI 표시·검색·원문 근거·취소 시험과 52부서 전체 흐름도 통과했습니다.
2. 외부 연결 가능한 실행 권한의 별도 프로세스에서 3부서 전체 흐름을 실행했습니다. strace로 자식 포함 **9개 프로세스**의 socket/connect/bind/listen/accept/sendto/sendmsg/recvfrom/recvmsg/getpeername/getsockname을 관찰했으며 **호출 0건**이었습니다. 차단 실패한 연결 시도도 관찰되지 않았습니다. 추적 파일을 `test-results/network`에 보관합니다.
3. GUI는 Linux offscreen 방식으로 창·표·검색·근거 표시·배치 취소를 시험했습니다. 외부 접속 가능한 별도 GUI 관찰 실행의 8개 프로세스·스레드에서도 소켓 호출은 0건이었습니다. 실제 Windows 화면 조작 시험이 아닙니다. Qt offscreen의 크기 힌트 경고는 있었으며 위 확인은 통과했습니다.
4. Python 소켓 방어가 명시적 socket 호출을 거부하는 별도 시험도 통과했습니다. 이는 ‘시도 없음’ 관찰과 다른 방어 기능 시험입니다.

Windows의 Qt·방화벽·관리자 동작과 PC 전체 통신은 미확인입니다. Linux 시험을 근거로 완전한 보안 인증을 주장하지 않습니다.

## 배포물 검증과 남은 일

Windows용 공식 CPython NuGet 파일과 6개 wheel을 포함했습니다. wheel은 공식 PyPI 해시와 대조했습니다. CPython 실행 파일의 PE x64 형식과 주요 DLL 존재, 배포 매니페스트, ZIP 구성을 확인했습니다. Windows 묶음의 모든 파일이 매니페스트와 일치했고, 소스 묶음에서 다시 가상 전체 흐름을 실행해 통과했습니다. Windows 코드를 Linux에서 실행·코드서명 검증한 것은 아닙니다.

남은 필수 현장 작업: Windows 11 실행, 관리자·방화벽 설정, 실제 망분리·통신 시도 관찰, 한컴이 만든 HWP/HWPX 대조, Excel에서 출력 확인, 기관 정답 검수, 실제 양식 매핑·산식·필수목록·보관규정 확정. 이 작업이 끝나기 전 실제 업무의 최종 결과를 맡기지 마세요.
